FOUR LAYERS, ON Cloudflare
layer 1 · Cloudflare
The network
How a visit reaches this website.
When you type the address, Cloudflare's DNS answers. The zone is signed with DNSSEC, a signature that lets anyone check the answer was not altered on the way. The connection is encrypted with TLS 1.3 at the least, and in browsers that support it not even the site's name travels in the clear. On the other side there is no server of our own: a Worker answers, a program Cloudflare runs in the data centre closest to the visitor.

layer 2 · Cloudflare
The cache
Which pages are kept ready-made, and when they are cleared.
In front of the Worker sits Cloudflare's cache, which keeps copies of pages in each data centre. If the page you ask for is already stored, it is delivered without running the Worker. Only pages that ask for it are stored, and publishing a change from the content management system (the CMS) clears, by tag, that page and every page that lists it.

layer 3 · Cloudflare
Compute
Where the code that builds each page runs.
The whole site is produced by a single Worker with Astro, a framework that assembles each page at the moment it is requested. Files that never change, such as styles, scripts and images, are served directly, without running any code. There is no server behind it, and before answering the Worker adds seven security headers to every page.

How what you see is drawn.
The interface is built with Astro and a single stylesheet. Fonts, scripts and images come from the site itself; the one thing fetched from outside is the visit counter from Cloudflare. The openings of each section pair restored photographs with a drawing animated in the browser.

One stylesheet declares every colour, radius and shadow, the column width and the spacing scale. CI rejects those values written anywhere else, except in marked blocks that imitate another product's interface.

5.2
Outside the site, the browser calls Cloudflare and nobody else: it downloads the Web Analytics script and sends it its measurements, with no cookies and identifying no one. Fonts, images and every other script are the site's own. Zaraz, Cloudflare's tag manager, loads on every page from this same domain and receives the answer you give in the cookie notice. If you accept analytics, it sends the visit to Google Analytics 4 from Cloudflare's servers: even then the browser never calls Google. If you decline, Google Analytics 4 never runs.

5.7
The cookie notice is the site's own. It is a card in the bottom-left corner, and the page keeps working behind it while you decide. Accept and Reject are two identical buttons, side by side. The notice has no close button and waits for your answer. “Cookie preferences”, in the footer, opens it again. Zaraz's own window is off because it blocks the whole page, and the cookie guide of Spain's data protection authority (AEPD) asks for less. It asks for Reject at the same level as Accept, a notice that stays until you answer, and withdrawal as easy as consent. Only your click passes the answer to Zaraz, through its consent API. Google Analytics 4 is not needed to count visits, since Web Analytics already does. It is here because this site is also a lab.

Delivery
How a change reaches production.
The code lives in a GitHub repository. Every change comes in as a reviewable proposal, a pull request, and goes through 27 steps of automatic checks (the continuous integration, or CI) against a local copy of the site. If they all pass, the preview deploys itself with wrangler, Cloudflare's deployment tool. Production is deployed by hand, and a guard refuses to overwrite a database that already holds content.

AI agents write most of the code, and the founder merges every change.
